## PR #16 review corrections

- Comment `4422761093`: anomaly disclosure uses whole words and phrases with
  supported inflections. Generic wording such as "Correlate the pressure readings
  with the logbook before diagnosing" no longer earns late-event disclosure
  credit; genuine "delayed" and "late event arrivals" statements still do.
- Comment `4422761153`: the overlapping firmware scenario records CPU overload
  and watchdog resets beginning after the software update. Only other causal
  modes call the update a distraction. The regression test checks both branches.
- Comment `4423131827` on `f790246`: retrospective challenge findings now follow
  the latest actual telemetry observation and event receipt, before incident
  reporting. This includes exporter gap recovery and completed maintenance plus
  subsequent healthy checks. Only the injection cohort's precursor clues retain
  pre-onset challenge timestamps; original18 records remain immutable. Four
  focused tests distinguish precursor chronology from retrospective findings.
- Comment `4423267238` on `a68589f`: sensor disclosure requires a bounded phrase
  connecting a sensor or gauge to its anomaly within one finding or check.
  A vacuum-leak diagnosis plus routine gauge comparison no longer earns credit,
  nor do disconnected fault/drift mentions. Focused examples cover connected
  wording, inflections, possessives and punctuation. This is a deterministic
  wording heuristic, not semantic entailment; thresholds remain unchanged.
- Regenerated the seed, manifest and all three dependent feedback files through
  their generators (feedback count 10, seed 42). No thresholds, original cases
  or frozen golden fixtures were changed.

## Measured live evidence (2026-10-30)

The approved diagnostics-only deployment shipped source `748307f` (merged as
`ae90cc5`). The original 791 fingerprints passed offline before deployment.
Fifteen typed, non-model readiness samples matched the same local source,
including corrected challenge logbooks. These samples are not a claim that all
791 fingerprints were verified against the deployed service. No infrastructure
provisioning or search-index reseeding was performed.

Exactly one measurement used the original `fae76ff` agent, the `748307f` harness
and deployed diagnostics, and `gpt-5.4-mini`, at concurrency one and three repeats.
It did not use Q1's evidence policy or L1's skill loading. The baseline covered
all 50 cases (150 results); the pre-registered ablation covered only the original
18 (54 results). The ablation removed "How to investigate", retaining the role
and answer rules; it did not alter tools, data, schemas or thresholds.

The baseline passes every unchanged gate. The deliberately ablated candidate
fails coverage (0.90) and knowledge use (0.70), so the completed experiment exits
1; this is not a fatal or incomplete run. Its failures remain retained.
Coverage's baseline 95% interval is approximately 0.859-0.952, so passing the
point-estimate gate does not establish a reliable margin above the threshold.

Paired hierarchical bootstrap intervals use matching original18 case/repeat
pairs, 2,000 samples and seed 42. For ablation minus baseline, coverage's 95%
interval is [-0.1333, -0.0407] and knowledge use's is [-0.9074, -0.6296].
Both are wholly negative overall and separately on train and test splits.
These are the two metrics meeting the planned ablation criterion. Hit-at-1/3
intervals include zero; no corresponding beyond-interval degradation is claimed.

The 32 challenge cases contribute 96 runs: hit-at-1 is 69/96 (0.71875), with a
95% interval of approximately 0.573-0.854. The point estimate is inside the
pre-recorded 0.30-0.80 headroom proposal; the entire interval is not. That range
was informational, never an added gate.
