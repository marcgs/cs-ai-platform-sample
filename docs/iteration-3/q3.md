# Q3: harder cases with causal ground truth

Status: offline implementation-ready, not complete. No live headroom or ablation
measurement, deployment or model call was performed during this preparation.

## Publication scope

Prepared on `it3/q3-ground-truth`, based on `78f82c7` from
`it3/l2-synthetic-feedback`, including Q2's reviewed harness and L2's feedback
generator, interchange contracts and dependency additions. This includes Q2's
`bb24bd8` optional Git provenance, `10d105b` summary zero-fill, and L2's
`8c35092` context-date, fixture and packaging fixes.

The latest integrated Q3-owned implementation supplies 50 scenarios: the original
18 clean cases and four examples in each of eight challenge categories. Causal
truth comes from generation, never agent output. Missing-machine prompts actually
withhold identity. Irregular telemetry retains observation times, and diagnostic
tools disclose collection and sensor anomalies without altering legacy results.

The manifest persists machine splits. The original18 regression cohort is
explicitly `SC-001` through `SC-018`; the 32 challenge cases and their errors are
report-only. All six added causal metrics are informational; thresholds are
unchanged. The suite does not include Q1's evidence policy or truthfulness
evaluator, L1's skill loading or L3's analysis.

Q2's platform harness and CLI files are unchanged by this delta, including
minimum-score metric handling and artifact collision protections. L2's source
labels and runtime corrections are retained. The domain README adds a dataset
card without replacing the L2 context-date contract. The three dependent feedback
fixture files are regenerated through the generator APIs with count 10, seed 42:
Q3 expands the seed-backed scenario and failure-mode populations, so the former
fixture no longer equals generation. The reproducibility assertion is unchanged;
generation is not restricted to original-only scenarios. The reviewed transcript
and feedback runtime code remain unchanged.

Known-cause challenge events include the mode's selected lookup code within the
compact four-event transcript. This fixes compatibility with L2's matching-event
citation contract without replacing its independently reviewed transcript code.
Original seed records and frozen tool-result fingerprints remain unchanged.

## Remaining acceptance and release prerequisites

The parent must integrate final Q2/L2 changes from main and rerun offline gates
before merge. A stacked pull request may be published earlier for parallel
review. Preserve those topics' reviewed platform, CLI and packaging fixes.

After merge, an approved `azd deploy diagnostics-mcp` must ship the Q3 seed,
domain package and tool implementation together. Run the golden test first. The
toolbox serves deployed data, not this worktree's seed. No infrastructure
provisioning or search-index reseeding is required by this additive dataset.

An intended hosted agent release requires the approved `azd deploy rca-agent`
from its actual candidate source and compatible local SDK resolution. Exported
requirements and function wheels must come from that checkout, not a stale
integration directory. Q3 alone does not change agent behavior.

Only then run scoped, serialized live measurements at concurrency one: preserve
the pinned pre-iteration baseline; measure challenge-category headroom; compare
the pre-registered investigation-step ablation on matching case/repeat cohorts
and unchanged gated metrics. Record actual agent, harness, dataset, tool and model
revisions and date privately. Confirm the proposed headroom interval before
measuring, and keep failed runs rather than rerunning for a pass.

The current CLI accepts repeated `--case` options. An approved 54-run
regression-only measurement must explicitly select `SC-001` through `SC-018`
with three repeats; the [eval README](../../evals/rca/README.md) provides the exact
selection command. Without it, report-only challenge cases also execute. A gate
declaration is not an execution filter.

The live `csai eval rca --target local` gate was intentionally skipped: this task
authorizes offline preparation only. No live acceptance or deployment is claimed.
