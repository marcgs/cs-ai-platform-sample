# L1: versioned RCA investigation skill

Status: implementation and frozen local/hosted validation recorded. These
measurements do not establish general behavioral equivalence.

The investigation procedure and answer rules are a bundled, versioned
`rca-investigation` skill. Agent creation puts the skill body in context exactly
once. The procedure text is unchanged from the pre-skill instructions.
Always-in-context is the default; progressive disclosure is not selected
without measured evidence.

Episodes accept optional skill metadata without requiring it on older records.
The installed wheel includes the skill, including when built from the source
distribution. The image's build-time import check also loads the skill.
Shared factory, spec, capture, diagnostic tools and evaluator behavior are
unchanged. Existing source labels and episode interchange remain intact.

This preparation is based on the integrated evaluation-harness and synthetic
feedback work. It excludes required-evidence enforcement, truthfulness
evaluation, challenge data and episode analysis.

Offline validation passed Ruff, formatting, Pyright and all 291 offline tests,
including the real scripted tool loop, failed-run skill metadata, legacy episode
compatibility and installed-wheel loading. The ignored local resolution uses
Agent Framework core 1.22.0 and MCP 1.30.0; no SDK constraint or index
configuration is changed. The unrelated fresh-resolution compatibility issue
remains outside this change.
The installed-wheel subprocess also executes the image's import-and-skill-load
guard. Those offline checks did not build a container; the later approved
deployment built and deployed the image from frozen revision `59d273d`.

The retained pre-skill measurement is not green: all 54 diagnoses were correct,
but `used_knowledge` was 0.4444444444444444 against its unchanged 0.70 minimum.
That failure remains retained. The integrated skill-plus-enforcement experiment
cannot isolate L1 and is not substituted for the control or the measurement below.

## Frozen isolated local measurement

The bundled-skill candidate ran from clean revision `59d273d`, without Q1
enforcement, on the unchanged original 18 cases, three repeats, local target,
concurrency one. The model was `gpt-5.4-mini`, with the original toolbox,
evaluators, thresholds and frozen machine splits.

The first attempt was cancelled during MCP tool discovery after 25 completed
case/repeats. Only rounded console observations survived; complete results and
episodes were not exported. This attempt remains partial/inconclusive, separate
from the recovery, with no reconstructed episodes or pooled scores. The traceback
does not establish whether the underlying cancellation was transient or an SDK
defect.

One full technical recovery used the same frozen candidate and preregistered
comparison, with immediate durable case/episode journals. It was not a rerun to
seek a passing quality score. It completed 54 unique case/repeats, with 54
distinct final, succeeded, real episodes tagged `rca-investigation` version
`1.0.0`. Each structured report exactly matches its captured episode output.
Those final episodes retain 431 complete, untruncated tool calls. The episode
journal retains 56 rows; this is not a claim of 56 distinct final episodes.

The unchanged aggregate gates passed:

| `schema_valid` | 1.0 |
| `hit_at_1` | 1.0 |
| `hit_at_3` | 1.0 |
| `evidence_grounded` | 1.0 |

All/train/test paired comparisons have no entirely negative difference interval
on any common metric. The overall candidate-minus-baseline knowledge interval

This is observational baseline-matching evidence on a small synthetic cohort,
not causal improvement attribution, formal equivalence or noninferiority.
The original baseline's knowledge-gate failure is not erased by this candidate's
passing aggregate.

## Hosted validation and API coordination

One hosted diagnosis verified the actual deployed `59d273d` candidate. The
response-derived episode ID and stored response ID matched exactly. Raw API
JSON contained `source="real"` and skill name/version
`rca-investigation` / `1.0.0`. The response completed, the episode succeeded,
`truncated` was an empty list, the structured outputs matched exactly and all
eight tool calls were fully captured. The endpoint's `@latest` route was
resolved against deployed-version metadata before and after the diagnosis.

The private validator's initial boolean interpretation of truncation metadata
was corrected to check the actual empty list and each tool's complete capture.
Fourteen private tests and a dry-run passed before the sole hosted inference;
there was no additional hosted run to repair the validator.

Exposing the additive metadata required a coordinated platform API deployment:
the older API serialized episodes without the new fields. The first deployment
payload inherited the private launch wrapper's umask 077 and could not be read
by the Functions worker. Rebuilding in a deployment child process with umask 022
repaired it. This was a wrapper-permission incident, not a demonstrated repository
packaging defect. No tracked runtime change was made for that repair.

resource publishing was authorized or performed; the approved agent deployment
was the `rca-agent` container, not an `azure.ai.skill` resource.

The measurements above are complete. Optional skill-resource exploration and
progressive-disclosure comparison remain separate work.
