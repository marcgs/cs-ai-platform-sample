## Canonical identity

`episode_analysis.vocabulary` exports:

```python
Category                        # the existing seven-category Literal
Condition                       # a closed Literal, not arbitrary text
CONDITIONS: dict[Condition, str] # canonical values and observational definitions
canonical_condition(value: str) -> Condition
cluster_key(category: Category, condition: str) -> str
```

The vocabulary combines catalog mechanisms FM-01 through FM-09 and their
pressure/temperature evidence with the existing observational failure taxonomy:

| Source | Canonical conditions |
|---|---|
| Catalog mechanisms | `stage_cooling_drift`, `chamber_vacuum_leak`, `source_energy_instability`, `reticle_gripper_wear`, `interferometer_contamination`, `controller_firmware_regression`, `purge_flow_restriction`, `lens_heating_drift`, `pressure_sensor_fault` |
| Catalog signal evidence | `pressure_telemetry`, `temperature_history` |
| Observational taxonomy | `shared_codes_after_software_update`, `unmapped_error_code`, `incomplete_duplicate_late_telemetry`, `prompt_injection_logbook`, `failed_diagnostic_tool`, `insufficient_discriminating_evidence` |

These are observed mechanisms or failure signatures, **not asserted answers**.
For example, omitted pressure evidence does not establish a vacuum leak.
Neither catalog loading nor classifier construction reads scenarios, generated
memberships or an answer key. New mechanisms need an explicit vocabulary change;
there is no catch-all free-text slug that silently creates another cluster.

Canonicalization case-folds and normalizes punctuation, then applies only the
explicit legacy aliases in `vocabulary.py`. For example,
`prompt_injection_in_logbook` and `logbook_instruction_overrode_procedure` map to
`prompt_injection_logbook`; `diagnosis_without_pressure_telemetry` maps to
`pressure_telemetry`. Unknown values fail validation and remain visible
classification errors, not fallback clusters. The structured-output JSON schema
advertises **only canonical enum values**, never these input aliases.

`Cluster.id` is `sha256(f"{category}:{canonical_condition}".encode()).hexdigest()[:16]`.
It does not include rationale wording, display text, score, membership, input
order or report rank. Category or mechanism changes deliberately change identity.
Changing explanatory descriptions does not change it. Cluster ordering still
uses the existing impact/frequency ranking.

Classifier v3 fingerprints the new prompt and enum schema. Old cache entries
and approved preflights are not reused. All frozen L3 pilot inputs, reports,
labels, caches, audit and benchmarks stay untouched; none is canonicalized or
rewritten in place. V1 reports lack the required review evidence and are not L9
promotion inputs. Historical benchmarking uses the frozen L3 implementation,
not an automatic migration that would misrepresent its original fragmentation.

## Category boundaries and TRAIN-only examples

No categories were merged and no routes changed. Definitions now distinguish
uncollected/unused evidence from evidence that was considered but outweighed,
bad source data from failed calls, and encountered injection from obeyed injection.
The primary demonstrated cause wins: obeyed injection, failed call, bad source
data, then knowledge/evidence handling. Do not invent an upstream defect.

Examples below and in the prompt are **counterfactual failure illustrations** on
existing TRAIN inputs, not claims that those cases actually failed this way.
No TEST example or fresh cohort/key informed these examples.

## L9 candidate/report contract

New JSON reports have `schema_version: "episode-analysis-v2"`.
`episode_analysis.models.Report.clusters` contains `Cluster` records with:

- `id`: the stable canonical key above; `category: Category`, `condition: Condition`.
- Existing route, handoff, impact, membership, representative IDs and context.
- `eval_cases: list[episode_analysis.models.EvalCase]`.

Every `EvalCase` has these **required** fields:

```text
episode_id: str
input: str
expected_category: Category
expected_failure_mode: str | None
expected_mode_basis: str                 # reviewer_consensus or unknown
tool_calls: list[dict[str, object]]       # full captured ToolCall records
capture_truncated: list[str]             # preserved Episode.truncated capture flags
capture_status: running | succeeded | failed
capture_created_at: datetime             # original episode lifecycle timestamps
capture_completed_at: datetime | None
review_notes: list[str]                  # retained compatibility/display field
review_summary: ReviewSummary
source_review_ids: list[str]             # sorted IDs of exactly source_reviews
source_reviews: list[diagnostics_domain.feedback_models.Review]
```

`ReviewSummary` remains exported from `episode_analysis.models`:

```text
episode_id: str
verdict: Literal["correct", "partially_correct", "incorrect"] | None
agreement: float                        # reliability-weighted verdict fraction
independent_reviewers: int
notes: list[str]
expected_mode: str | None
root_cause_support: float
```

The summary and expected mode come from the **same cleaned review rows** as the
IDs. Each source row carries its episode, source, ID and complete `Feedback`
(reviewer identity, verdict, actual root cause, note, submission time).
This extra evidence lets L9 check distinct named supporters and actual cause
claims rather than infer a supporting count from a fraction.

Review cleaning retains one latest row per normalized reviewer identity and
episode. Anonymous rows form at most one voice and cannot support an accepted
verdict. Content breaks same-time ties; only fully identical content uses ID as
a final provenance tie-breaker. Repetitions do not add votes. Conflicting reuse
of a review ID fails preparation instead of producing ambiguous citations.
Embedded feedback receives the explicit ID `embedded-<episode-id>` and is
included as a normal source row; it does not invent an external review.

The consensus policy is unchanged: at least two named supporters and more than
60% reliability-weighted verdict agreement. `expected_mode` additionally needs
at least two of those supporters to name the same actual cause and a strict
majority of named verdict supporters. `root_cause_support` is the winning cause
count divided by named verdict supporters, **not** by all independent reviewers
and not reliability-weighted. A cause can remain unsupported even when the
verdict is accepted. L9 must not substitute a cluster condition or agent output
for an absent expected mode.

L9 should require the v2 evidence, verify the key with `cluster_key`, corroborate
summary/IDs against source rows, and separately enforce its consensus, replay,
duplicate and expert-review rules. These records are candidates, not an
admission decision or ground truth. The analysis still excludes uncertain
verdicts; missing root-cause consensus stays visible on retained candidates.
`Report.reviewer_agreement` carries the cohort-level reliability weights used
for consensus. Re-estimating reliability from candidate rows alone changes the
population and is not a faithful check of the stored weighted agreement.
Markdown now shows keys, consensus statistics and escaped source IDs; exact
source rows and captured tool calls are in JSON.
