### Q11 retry design — proposed, not implemented

The recovery proposal deliberately distinguishes an immutable agent measurement
from its cloud publication attempts. Adopting it changes the strict
one-cloud-run-per-measurement contract; it requires an explicit user decision.

1. Default publishing stays idempotent and never starts a retry. A separate
   explicit infrastructure-retry option identifies the previously failed run.
   It is not an agent rerun, a metric change or a quality-seeking resume.
2. Admission requires the retained original submission receipt, identical
   frozen measurement/provenance, the canonical evaluator definition, a terminal
   `failed` run with the specific `EvaluationSessionNotBound` startup error,
   zero total rows and a fully paginated empty output-item listing. Missing or
   ambiguous evidence, other errors, partial grades and quality failures stop it.
   A null errored count alone is not evidence of zero evaluated rows.
3. The original failed run, receipt and diagnostics remain intact. A separate
   attempt receipt binds the measurement, endpoint, judge and prior run. The
   cloud run name visibly links to that prior run, while all frozen metadata
   remains unchanged; do not exceed the metadata limit by dropping provenance
   fields or silently replacing their meaning.
4. Repeating the same explicit retry request resumes that attempt, including
   after timeouts or uncertain submission outcomes. Shared measurement
   coordination serializes original publication and retries. Remote
   reconciliation distinguishes registered retry lineage from accidental
   duplicates; unknown or conflicting runs still stop submission.
5. Every new attempt needs separate operator approval and a fresh cost
   disclosure. There is no automatic retry loop, receipt reset, failed-run
   deletion, capability-host recreation or new measurement identity.
6. Focused offline boundary tests must cover admission and rejection, retained
   failures, unchanged rows/version metadata, duplicate/ambiguous outcomes and
   concurrent copies before any live invocation. One canonical suite definition
   remains, and Q10 remains blocked without fabricated scores.

At this preparation checkpoint the design had not been adopted or implemented,
and the storage addition was not applied. The subsequent approval and
implementation are recorded below; the failed publication remains retained.

## Enforcing unknown legacy origin

Missing receipt evidence is now an enforced non-submitting error, not an
operational warning. New captures persist `publication_coordination: shared-v1`
in their frozen manifest. The disk adapter accepts that marker only for a
certificate-verified complete capture. It is excluded from publication hashing
and SDK payloads, preserving existing measurement identities and scores.

Without that provenance or a shared receipt, a legacy record cannot initiate
publication. The check runs before credentials or SDK lookup/create operations.
This includes a copied legacy archive whose original pending receipt exists
elsewhere and is not yet imported. A never-published legacy archive is also
blocked: missing receipts or empty remote listings cannot establish non-submission.

Evidence in the current legacy receipt directory is imported automatically.
`csai --no-azd eval publish <archive> --legacy-receipts <original-receipt-directory>`
identifies positive original evidence when publishing elsewhere. The directory
must contain the matching receipt; absent or empty origins are refused without
creating them. This option cannot assert “never submitted” or override trust.
Known evaluation IDs are retrieved directly, never recreated from an empty list.
Pending outcomes block new judge runs; accepted runs are reused only after their
remote measurement identity matches. Conflicting evidence fails closed.

If original evidence is unavailable, explicit legacy reconciliation is required;
there is no flag authorizing a fresh legacy submission without evidence. Already
shared receipts continue to support older captures, and new certified captures
publish normally. Confirmed 403/429 creation rejection still permits safe retry;
ambiguous timeout/server failure still retains pending state.

Offline regressions cover the first copied-legacy invocation before source import,
explicit positive-origin import with empty remote listings, unavailable and empty
origins, public CLI refusal, rejected uncommitted marker claims and identity-checked
