This item is committed separately on top of Q8. The live local measurement
below used the **uncommitted integration snapshot**, with `harness_dirty=true`;
neither per-item commit was live-tested individually. Local commit validation
is offline only. No publishing, provisioning or hosted smoke test is claimed.
The Q8 + Q9 partition passed **454 full offline tests**, repository-wide Ruff

`az bicep build --file infra/main.bicep --stdout` before its local commit.
Its new environment was restored from the ignored integration lock after an

reported an available Bicep upgrade; no upgrade or Azure write was performed.

Publishing reads Q8's saved run. It does not run the agent, change a score, or
change the local gate. The same publisher serves `csai eval publish` and a run's
`--publish`. Publishing writes evaluations and evaluator versions to Foundry;
run it only after approval.

Rows retain case identity, repeat, split, category, cohort, input, response,
captured tool calls, pinned tool definitions, reviewer/dataset ground truth,
applicable code scores and the synthetic source label. Version metadata comes
from the run record, not from the checkout at publishing time.

Code-based custom evaluators return recorded scores. The four informational
judges are task adherence, intent resolution, coherence and tool-call accuracy.
The latter receives tool definitions as well as calls. Old records without
those definitions are not silently reinterpreted using today's tools.

One evaluation is reused for each suite. An incompatible evaluator definition
is rejected rather than creating duplicate suite evaluations or changing an
old measurement's meaning.

Offline verification: 19 publisher/adapter tests passed, including the public
`csai eval publish` path against actual durable records with the Foundry client
faked. Ruff lint/format and strict Pyright passed. The integrated iteration
passed all 481 offline tests.

## Outstanding acceptance and limitations

- The host must be provisioned only after a reviewed what-if and explicit
  approval, then checked for `Succeeded` and followed by a hosted diagnosis.
- Publishing and judge traffic need separate approval. No evaluation or
  evaluator version was written to Azure during implementation.
- No live metric-parity or judge comparison is claimed.
- Foundry's documented code evaluator contract returns a float only. A sparse
  local metric has no valid score on an inapplicable row. The user chose to keep
  one run per measurement and mark sparse parity blocked. All applicable
  scores remain in rows; only metrics applicable to every row get code
  evaluators. Runs containing plumbing failures keep scores in rows without
  mirroring code aggregates, since the local aggregate excludes those runs.
  Their metadata explicitly records `blocked:sparse_or_plumbing`. The mirror
  still raises defensively for missing input rather than inventing a zero,
  and the publisher reports any evaluator errors as failure. Full sparse
  metric parity must be verified before Q9 acceptance. A local gate pass is
  never inferred from Foundry's aggregate.
- A new partial run whose metric schema differs from the suite's existing
  evaluation requires a reviewed evaluation-definition migration.
- The approved live local eval after harness/capture changes completed with
  exit 0, as recorded below. It does not satisfy publishing, judge comparison
  or Foundry metric-parity acceptance.

AGENTS.md, ADR 0004 and the platform tour retain their live-infrastructure
claims until a published run actually completes, as the plan requires.

## Integration correctness review

Offline review fixed three reporting-boundary issues:

- An actual empty case-level tool-definition snapshot stays empty; it no longer
  falls back to run-level definitions. Tool calls without captured definitions
  still fail publishing before authentication.
- Ordinary unexpected adapter errors are normalized at the public publishing
  boundary. `--publish` preserves both passing and failing local gates, while
  standalone publishing reports the error and exits 2. Cancellation still propagates.
- Plumbing-only measurements with no scores now explicitly mark metric parity
  `blocked:sparse_or_plumbing`, not `unverified`.

The focused Q8/Q9 suite passed **131 offline tests**. Added regressions failed
before the fixes; targeted Ruff lint/format, strict Pyright on modified modules
and `git diff --check` passed. During the offline correctness review, no
publishing, judge/model calls, authentication or Azure writes were performed.
Sparse parity remains deferred; no metric
applicability, code aggregation or local gate was weakened.
