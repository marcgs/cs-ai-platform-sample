## Record contract for Q9

Public module: `cs_platform.eval_runs`.

```python
load_run(results_dir: Path) -> RunRecord
read_run(results_dir: Path) -> RunRecord  # alias
rebuild_report(results_dir: Path) -> RunRecord
```

The argument accepts an enclosing results directory containing exactly one journal,
the journal directory itself, or the legacy JSONL output path. When several journals share
a directory, pass the journal explicitly. Reading/rebuilding needs no agent imports,
evaluator execution, Azure settings or credentials.

For `--output <directory>/<stem>.jsonl`, schema v1 uses:

| Path | Role |
|---|---|
| `<stem>.run/manifest.json` | Frozen run configuration, written before any target starts |
| `<stem>.run/events.jsonl` | Authoritative append-only journal; one typed event per committed line |
| `<stem>.run/episodes.jsonl` | Derived actual episodes, appended immediately and rebuildable |
| `<stem>.jsonl` | Compatible `CaseResult` JSONL, appended immediately and rebuildable |
| `<stem>-transcripts/<case-hash>-<repeat>.json` | Compatible escaped-link transcript artifacts |
| `<stem>.summary.json`, `<stem>.html` | Derived summary, gate and static private report |

`RunManifest` has:

- `schema_version: Literal[1]`;
- `suite: str`;
- `cases: tuple[EvalCase, ...]`, containing the selected input, `expected`, optional `truth`
  and assigned `split`, without changing the manifest generator or historical case bytes;
- `cohorts: dict[str, str]`, keyed by case ID: explicit case cohort when present, otherwise
  `original` for the regression cohort and `challenge` for report-only cases;
- `thresholds: Thresholds`, `gate_case_ids: frozenset[str] | None`;
- `metadata: RunMetadata`;
- `result_filename: str`, a validated basename;
- `concurrency: int`, `retries: int = 2`, `backoff_s: float = 20`.

`RunMetadata` retains `agent_revision`, `harness_revision`, `harness_dirty`, `model`,
`target`, `repeats` and `started_at`. It adds nullable `agent_version`, `skill_version`,
`dataset_version`, `tool_definitions`, and `source: Literal["synthetic", "unknown"]`.
The CLI pins local bundled agent/skill versions and a SHA256 of the full case manifest
before filtering or execution. Hosted versions remain unknown rather than being inferred
from local code. Run-level tool definitions may remain `None`: actual discovered schemas are
captured per attempt/case in `RunOutput.tool_definitions`, not rebuilt from static wrappers.
Metadata source describes the dataset: actual runs over fictional incidents are labeled
`synthetic` here, while their captured `Episode.source` remains `real`.

Each event includes an ISO timestamp `at` and a discriminated `kind`:

| Kind | Other fields |
|---|---|
| `started` | `key: CaseRunKey` |
| `attempt_started` | `key`, `attempt: int` |
| `attempt_finished` | `key`, `output: RunOutput` (including attempt count and full available tool trace) |
| `episode` | `key: CaseRunKey | None`, `attempt: int | None`, `episode: Episode` |
| `case_finished` | `result: CaseResult` |
| `finished` | `status: complete | incomplete`, `error: str | None` (exception type only) |

`CaseRunKey` is the frozen pair `{case_id: str, repeat: int >= 1}`.
Case/attempt keys are task-local, so concurrent episodes do not rely on incident text,
timestamp matching or output order. Failed retry outcomes and their actual episodes remain
in the journal even when a later attempt succeeds. Interrupted attempts are not scored or
turned into fake completed cases.

`RunRecord` exposes:

- `manifest: RunManifest`, `events: list[RunEvent]`, `result: SuiteResult`;
- `status: Literal["complete", "incomplete"]`;
- `never_started: list[CaseRunKey]`, `interrupted: list[CaseRunKey]`;
- `failures: list[str]`: unchanged gate failures plus an incomplete-run failure when needed;
- `journal_warning: str | None`;
- `.episodes: list[Episode]`, `.attempts: list[AttemptFinished]`;
- `.suite() -> EvalSuite`, with frozen cases, truth, thresholds and gate IDs, no evaluators.

`RunOutput.tool_definitions: list[dict[str, JsonValue]] | None` snapshots the actual entered
local agent's ordinary function tools and discovered MCP functions before its model/tool
loop starts. Schemas come from `FunctionTool.to_json_schema_spec()` and retain raw prefixed
names. Completed and normally failed attempts retain this snapshot. Local agents with no
functions record `[]`; legacy and hosted outputs whose schemas cannot be discovered remain
`None`. An interrupted case may have no returned output/schema; its captured episode is still
retained independently. Publishing must not infer missing definitions from wrapper copies
or from today's tool deployment.

Q9 should publish from `load_run`, using `record.result.cases` and manifest truth/cohorts.
It must use `record.failures`/`record.status`, not only `SuiteResult.failures()`, when
reporting completion. It must not synthesize missing episodes, retry failed case-runs,
or load current versions in place of unavailable pinned metadata.

## CLI and durability

`csai eval rca` and the bare default-agent `csai eval --options` remain supported.
`csai.eval_cli.eval_app` owns the command group and offline `report` subcommand.
The separate Q9 commit adds its `publish` command and adapts the runner's
`--publish` flag to `csai.eval_publish.publish_record(path) -> str`.
Q9 normalizes publishing errors to gate-preserving warnings; standalone
publishing errors exit 2. This intermediate Q8 commit retains legacy publishing.
The run's normal gate reads the same disk snapshot as the report command.

Each event append flushes and fsyncs its file and directory. Results are committed before
derived transcript export. Reports use exclusive sibling staging files and atomic replacement;
existing run destinations are rejected before target creation. Export symlinks are refused.
HTML escapes all case data and retains the restrictive content security policy.

Graceful cancellation/fatal failure cancels and awaits active sibling tasks before recording
`incomplete`. The summary enumerates all selected case/repeat keys that never started,
and those that started without a completed scored result. The actual middleware episode
records a cancelled tool and propagates cancellation; it is not reconstructed from a score.
Successful prior records survive cancellation between cases, inside a tool call and while
exporting episodes or HTML.

A hard stop cannot write a final marker. Missing final status, missing results or an
unterminated final journal line mean incomplete. Only that last uncommitted fragment may
be ignored; newline-terminated corruption is rejected. Rebuilding never repairs the journal.
Unrecoverable disk failures can prevent a final summary; retained events remain the source
for rebuilding after the fault is corrected. Store failure or repeated cancellation can leave
an episode unavailable, and it remains unavailable.

Pre-Q8 exports have no frozen run selection or durable completion marker. They are not
silently imported as complete runs, and missing episodes cannot be recovered from scores.

## Integration correctness review

Offline review found and fixed two reader issues:

- Journal framing now splits only on the committed newline delimiter. A carriage
  return cannot make committed corruption look like an ignorable torn tail.
- A result's gate membership must agree with the frozen manifest. A conflicting
  result is rejected rather than silently removing a regression case from the gate.

The focused capture, harness, reader, reporting and public CLI/publisher suite
passed **131 tests** using the existing dependency environment, worktree source
roots and worktree-local test artifacts. Targeted Ruff lint/format, strict
Pyright on the modified modules and `git diff --check` passed. New regressions
were observed failing before the fixes. No agent, evaluator, threshold, cohort
selection or cloud configuration was changed. Subsequent approved live evidence follows.
